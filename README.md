# Wellknown Workspaces for Claude

Your consulting workspaces in Claude: search a workspace's documents with citations, run your
firm's own playbooks, and check the claims of every answer. This works in claude.ai, Claude
Desktop, Cowork and Claude Code.

> This repository is generated by [pluginpack](https://github.com/gleanwork/pluginpack). Please
> don't open pull requests against it; contact Wellknown instead.

## Two parts: the connector and the plugin

The **plugin ships skills only**: no `.mcp.json`, no MCP server. A server that arrives through a
Claude plugin never renders Wellknown's apps (the workspace picker, the Claims Panel, the upload
panel), a known Claude bug ([anthropics/claude-ai-mcp#274](https://github.com/anthropics/claude-ai-mcp/issues/274)).
So the server reaches Claude as a **connector**, and the plugin teaches Claude how to use it.

**Skills without the connector do nothing. Add both.** The connector URL is:

```
https://mcp.wellknownlabs.com/v1/mcp
```

## For administrators: set it up once for your organisation (recommended)

1. **Add the connector.** In claude.ai, go to **Organization settings → Connectors**, add a custom
   connector with the URL above, and name it **Wellknown Workspaces**.
2. **Sync the marketplace.** Go to **Organization settings → Plugins & skills → Marketplaces →
   Add → Sync from GitHub**, and enter `wellknown-labs/claude-plugins`.
3. Set the plugin to **Required** or **Installed by default**. On Enterprise, you can do this per
   group with **Group access…**.

Members then have both in web chat, the Desktop Chat tab and Cowork, and sign in to Wellknown
Workspaces the first time they use it. Claude Code gets the organisation's connectors and synced
plugins for members signed in with their claude.ai account (Claude Code v2.1.273 or later).

**Machines that don't sign in to Claude Code with claude.ai** (API keys, Bedrock, Vertex) get the
plugin from managed settings, and the server from `claude mcp add` or the managed MCP
configuration (`managed-mcp.json`):

```json
{
  "extraKnownMarketplaces": {
    "wellknown": { "source": { "source": "github", "repo": "wellknown-labs/claude-plugins" } }
  },
  "enabledPlugins": { "workspaces@wellknown": true }
}
```

```
claude mcp add --transport http workspaces https://mcp.wellknownlabs.com/v1/mcp
```

Claude Code renders no MCP apps, so nothing is lost by connecting it this way.

## For individual users

1. **Add the connector.** In claude.ai or Claude Desktop, go to **Customize → Connectors**, add a
   custom connector with the URL above, and sign in. (Skip this if your administrator has.)
2. **Install the plugin.** In **Customize → Plugins → Add marketplace**, enter
   `wellknown-labs/claude-plugins` and install **Wellknown Workspaces**. If you're signed in with
   claude.ai, it also reaches Claude Code.
3. **Claude Code only:**

   ```
   claude mcp add --transport http workspaces https://mcp.wellknownlabs.com/v1/mcp
   /plugin marketplace add wellknown-labs/claude-plugins
   /plugin install workspaces@wellknown
   ```

## The first time you use it

Ask anything about your workspace. Claude connects to Wellknown Workspaces, and then:
1. You sign in.
2. You approve Claude once on Wellknown's site.
3. In each conversation, you choose which workspace Claude may use.

## Network access for downloads

When Wellknown Workspaces hands Claude a document to work on in code execution, Claude's sandbox
needs network access to `mcp.wellknownlabs.com`. A plugin cannot allow-list domains: an
administrator does it in the host's settings.

- **claude.ai, Claude Desktop and Cowork:** **Organization settings → Capabilities → Code
  execution**, and add the domain under additional allowed domains for network egress.
- **Claude Code:** in managed settings, add the domain to `sandbox.network.allowedDomains`, and
  allow `WebFetch(domain:mcp.wellknownlabs.com)` under `permissions.allow`.
